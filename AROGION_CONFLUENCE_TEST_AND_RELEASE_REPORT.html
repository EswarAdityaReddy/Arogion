1. Project overview

Arogion is a cross-platform Flutter healthcare application. The application provides authentication, patient profile management, doctor and hospital discovery, appointment booking, prescription and medication management, local medication reminders, maps/location features, and Agora-based video consultation.

6. Database and data ownership

The application uses Firebase for identity and Supabase for application data. The Firebase UID is mapped to the Supabase users.firebase_uid value and is used by the data-access layer to locate the application user row.

Data areaCanonical sourceApplication usage
Identity/profilesupabase_schema.sql users table plus Firebase AuthRegistration, login mapping, profile display and profile updates.
Healthcare catalogsupabase_schema.sqlHome categories, hospitals, doctors, assignments, treatments, treatment pricing and availability.
Appointmentssupabase_schema.sql appointments tableSlot selection, booking, appointment display, QR/ticket data and status updates.
Medication subsystemAROGION_DATABASE.sqlMedication records, dose alarms, intake history and alarm upsert operation.
FilesSupabase Storage buckets referenced by the serviceProfile images and medical reports.
Deployment rule: Run supabase_schema.sql for the broader application schema and use AROGION_DATABASE.sql as the only medication schema handler. Keep seed data separate from production deployment and inject user/environment values rather than hard-coding them.

8. Production notes

Authentication: Firebase Auth should be the only credential authority. Do not use a plaintext password field or direct password comparison in application data. Remove or disable any legacy basic-password path before production.
Secrets and keys: Move environment-specific Supabase values, Maps keys, Firebase configuration and Agora credentials into approved configuration management. Use restricted Maps keys and short-lived Agora tokens.
Data access: Keep row-level security enabled. Production policies must restrict profile, appointment, medication, alarm and intake records to the authenticated user or approved service role; avoid permissive USING (true) policies for private data.
Release configuration: Replace debug signing with protected release signing, maintain separate development, staging and production backend projects or namespaces, and keep generated folders such as build/ and .dart_tool/ out of source control.
